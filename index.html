About this project

API, pipeline and significance

🌐 API used

Weather data comes from WeatherAPI.com (current.json endpoint). Each call returns temperature, humidity, wind, pressure and more for one city. The producer splits every response into one message per metric.

🔧 Pipeline implemented

WeatherAPI→ producer.py→ Kafka→ Spark Streaming→ MongoDB Atlas→ Streamlit / UI
  • Kafka carries live readings; the Live page consumes them every 15 seconds.
  • Spark parses, validates and aggregates the stream into time windows.
  • MongoDB Atlas stores raw and aggregated data for the History page.

🎯 Significance of the dashboard

The dashboard turns raw weather readings into something people can act on: spotting heat spikes, comparing cities, and seeing how conditions trend over hours or days. Separating the live and historical views also shows how a streaming system serves both immediate monitoring and long-term analysis, a pattern that applies to any IoT or sensor workload.
